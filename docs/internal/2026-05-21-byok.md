# Secret Storage

## Storage model

Provider credentials must be recoverable for upstream requests. Every
`provider_key` row therefore stores:

- `token_ciphertext`: AES-256-GCM ciphertext bound to the row id and owning
  organization with additional authenticated data
- `token_masked`: a display-safe preview
- `token_hash`: an HMAC-SHA-256 fingerprint used for attribution

Gateway API keys, platform secret keys, internal end-user principals, and
end-user session tokens do not need to be recovered. They store keyed
HMAC-SHA-256 fingerprints instead. API-key rows also store a masked preview.
The intentionally public `platform_publishable` identifier is stored in the
display field so it can be returned to clients.

The secret-bearing tables do not contain plaintext token columns. Reads never
fall back to plaintext storage.

## Encryption

Provider-key ciphertext uses the versioned
`llmgw:v2:<kid>:<iv>:<ciphertext>:<tag>` format. The key id selects the matching
entry from `GATEWAY_API_KEY_HASH_SECRET`, which is a comma-separated keyring
with the current secret first. HKDF domain-separates the AES data key from the
HMAC key derived from the same secret.

Additional authenticated data is `provider_key|<row id>|<scope>`. Organization
credentials use their organization id; managed credentials use the fixed
`llmgateway:managed` scope. Moving ciphertext between rows or scopes fails GCM
authentication.

## Writes and reads

Provider-key writes generate the row id before encryption, then persist the
ciphertext, mask, and fingerprint together. `readProviderKey()` always decrypts
`tokenCiphertext`; malformed, tampered, or undecryptable values fail loudly.

Gateway and session authentication fingerprints the presented bearer against
every retained keyring entry and queries `token_hash`. New fingerprints use
the first keyring entry. Full secrets are returned only from the create or roll
request that generated them.

API responses use explicit allowlists and never include ciphertext or
fingerprints unless the fingerprint is an intentional operator-facing field.
Provider validation errors are redacted before logging or returning them.

## Rotation

Prepend the new secret to `GATEWAY_API_KEY_HASH_SECRET` on every service. Keep
the prior entries while provider ciphertext and authentication fingerprints
still depend on them. Re-encrypt provider credentials and roll one-way-hashed
bearer secrets before removing an old entry.

Historical `log.usedApiKeyHash` values use the key that was current when the
request ran and are not rewritten during rotation.
