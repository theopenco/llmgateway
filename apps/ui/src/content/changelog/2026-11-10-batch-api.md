Running an eval set, an enrichment job or a backfill through the gateway meant writing your own queue: cap the concurrency, back off on `429`, resume after a crash, and keep track of which lines failed. The new **Batch API** does that for you. Upload a JSONL file, create a batch, and download the results when it finishes.

It follows OpenAI's Batch API, so the OpenAI SDKs work once the base URL points at the gateway.

## From file to results

Each line of the input file is one request. Its `custom_id` comes back on the result, and `body` is the same JSON you would send to the endpoint directly:

```json
{"custom_id": "review-1", "method": "POST", "url": "/v1/chat/completions", "body": {"model": "gpt-4o-mini", "messages": [{"role": "user", "content": "Summarize: ..."}]}}
{"custom_id": "review-2", "method": "POST", "url": "/v1/chat/completions", "body": {"model": "gpt-4o-mini", "messages": [{"role": "user", "content": "Summarize: ..."}]}}
```

Upload it, then create the batch:

```bash
curl https://api.llmgateway.io/v1/files \
  -H "Authorization: Bearer $LLM_GATEWAY_API_KEY" \
  -F purpose=batch \
  -F file=@requests.jsonl

curl https://api.llmgateway.io/v1/batches \
  -H "Authorization: Bearer $LLM_GATEWAY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "input_file_id": "file-abc123",
    "endpoint": "/v1/chat/completions",
    "completion_window": "24h"
  }'
```

Poll the batch. Once it is `completed`, `expired` or `cancelled`, download the files it produced:

```python
import os

from openai import OpenAI

client = OpenAI(
    base_url="https://api.llmgateway.io/v1",
    api_key=os.environ["LLM_GATEWAY_API_KEY"],
)

batch = client.batches.retrieve("batch_abc123")
print(batch.status, batch.request_counts)

if batch.status in ("completed", "expired", "cancelled"):
    if batch.output_file_id:
        output = client.files.content(batch.output_file_id).text
    if batch.error_file_id:
        errors = client.files.content(batch.error_file_id).text
```

Requests that returned a 2xx response land in the output file. Everything else, including cancelled requests and requests that did not finish within the window, lands in the error file. A batch has each file only when it has lines for it, and both keep the input order.

## Three endpoints, any model they accept

| Batch endpoint         | Models           |
| ---------------------- | ---------------- |
| `/v1/chat/completions` | Chat models      |
| `/v1/responses`        | Chat models      |
| `/v1/embeddings`       | Embedding models |

The model is part of each line's body, so one batch can send different lines to different models. Every line runs through the normal gateway path: routing, fallback, caching, IAM rules, guardrails and usage limits apply, and each request shows up in your logs with the source `llmgateway-batch`. Streaming, realtime, image and video models are not supported. The [models page](https://llmgateway.io/models?batch=true) marks every model that works in a batch.

## What gets retried

- **Rate limits and empty balances wait.** A `429`, an overloaded gateway (`529`) or insufficient credits (`402`) does not fail a request. It waits and retries until the window ends, so a batch resumes after you top up.
- **Provider outages are retried.** `502`, `503`, `504` and a `500` with code `upstream_error` are attempted up to three times. These errors are not billed, so a retry never charges twice.
- **A request with an unknown outcome is not retried.** If the connection drops mid-request or the request times out, the line fails with `request_failed`; if the worker restarts while it runs, it fails with `request_interrupted`. Such a line may still have been billed, but its result is lost.

## Same price as a live request

Each line is billed at the same per-token price as the same request sent live, and there is no fee for storing batch files. Discounts that providers offer on their own batch APIs are not passed through, because the gateway runs each line as a regular request. The Batch API saves you the queueing code, not money.

## Limits

| Limit                                | Value   |
| ------------------------------------ | ------- |
| Requests per batch                   | 50,000  |
| Input file size                      | 50 MB   |
| Completion window                    | 24h     |
| File and batch result lifetime       | 30 days |
| Batches in progress per organization | 100     |

Batch files hold your prompts and completions. They are kept for 30 days, or until you delete them, regardless of your data retention setting. While zero data retention is active, uploading files and creating batches return `400` with code `zdr_storage_conflict`.
