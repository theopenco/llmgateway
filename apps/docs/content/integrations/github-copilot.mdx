The `github-copilot` provider routes requests through the OpenAI-compatible [Copilot API](https://github.com/features/copilot) using your own Copilot subscription — chat completions and embeddings, with the gateway's usual routing, logging, usage limits, and audit on top.

It is **BYOK-only**: you connect a GitHub account that has an active Copilot subscription, and requests are billed against that subscription's premium-request allowance rather than per token. There are no LLM Gateway credits involved, so the mappings carry $0 token prices in the catalog.

<Callout type="warn">
	Your Copilot subscription's terms and premium-request limits apply to requests
	routed this way. Use an account you are entitled to automate, and expect model
	availability to vary by Copilot plan.
</Callout>

## How authentication works

The stored credential is a long-lived GitHub OAuth token (`gho_...`/`ghu_...`). On each request the gateway exchanges it for the short-lived Copilot API bearer token (cached until shortly before expiry) and calls the Copilot API host for your plan:

| Copilot plan | API host                                   |
| ------------ | ------------------------------------------ |
| Individual   | `https://api.githubcopilot.com`            |
| Business     | `https://api.business.githubcopilot.com`   |
| Enterprise   | `https://api.enterprise.githubcopilot.com` |

## Connect your account

<Steps>
<Step>
### Add the Provider Key

1. Log into the [LLM Gateway Dashboard](https://llmgateway.io/dashboard)
2. Go to **Provider Keys** in the sidebar and click **Add Provider Key**
3. Select **GitHub Copilot**

</Step>

<Step>
### Sign in with GitHub

Click **Sign in** — the dialog shows a one-time code and a link to
[github.com/login/device](https://github.com/login/device). Enter the code
there, approve the authorization, and the OAuth token is filled in
automatically.

Alternatively, paste a GitHub OAuth access token you already have (for
example one minted by another Copilot-enabled tool).

</Step>

<Step>
### Pick your Copilot plan

Select **Individual**, **Business**, or **Enterprise** so requests go to the
matching API host, then click **Add Key**. The gateway validates the key by
performing the token exchange and a live chat completion — if the account has
no active Copilot subscription, the key is rejected.

</Step>

<Step>
### Send a request

```bash
curl -X POST https://api.llmgateway.io/v1/chat/completions \
  -H "Authorization: Bearer YOUR_LLMGATEWAY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "github-copilot/gpt-4o",
    "messages": [{ "role": "user", "content": "Hello from Copilot!" }]
  }'
```

Embeddings work the same way via `/v1/embeddings` with
`github-copilot/text-embedding-3-small`.

</Step>
</Steps>

Browse the available Copilot mappings at [llmgateway.io/models](https://llmgateway.io/models?provider=github-copilot). GitHub gates API model availability by plan, so a model listed there can still be unavailable on your account — use the key's **Allowed models** restriction to pin the ones your plan serves.

## Self-hosted deployments

For a self-hosted gateway you can configure the credential via environment variables instead of a provider key:

| Variable                         | Purpose                                                             |
| -------------------------------- | ------------------------------------------------------------------- |
| `LLM_GITHUB_COPILOT_OAUTH_TOKEN` | GitHub OAuth token of the Copilot-subscribed account                |
| `LLM_GITHUB_COPILOT_BASE_URL`    | Copilot API host override (e.g. the business/enterprise host)       |
| `LLM_GITHUB_COPILOT_TOKEN_URL`   | Token-exchange endpoint override for GitHub Enterprise Server       |
| `GITHUB_COPILOT_CLIENT_ID`       | OAuth app client id used by the dashboard device flow (API service) |

## Using LLM Gateway inside Copilot

This integration is the other direction of the [GitHub Copilot app guide](/guides/github-copilot): there, LLM Gateway acts as a BYOK provider _inside_ Copilot. The Copilot CLI and [Copilot SDK](https://github.com/github/copilot-sdk) accept any OpenAI-compatible endpoint, so you can point them at `https://api.llmgateway.io/v1` with an LLM Gateway API key:

```js
const session = await client.createSession({
	model: "claude-sonnet-4-5", // any tool-calling model in the catalog
	provider: {
		type: "openai",
		baseUrl: "https://api.llmgateway.io/v1",
		apiKey: process.env.LLMGATEWAY_API_KEY,
	},
});
```

Both directions compose: an agent built on the Copilot SDK can run against LLM Gateway, while the gateway routes other traffic to your Copilot subscription.

## Troubleshooting

### "the account has no active Copilot subscription"

The token exchange was rejected. The connected GitHub account has no active Copilot subscription, or the token was revoked — reconnect via the device flow.

### A model 400s with "model not supported"

GitHub feature-flags API model availability per plan; the Copilot API often exposes fewer models than Copilot Chat's UI. Restrict the key's **Allowed models** to the ones your plan serves via the API.

### Requests count against premium requests

That is how Copilot bills API usage — monitor consumption in your GitHub Copilot settings, and put an org [rate limit](/features/routing) in front if you need to cap it.
