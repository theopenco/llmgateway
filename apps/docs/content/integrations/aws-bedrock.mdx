AWS Bedrock is Amazon's fully managed service that provides access to foundation models from leading AI companies. This guide shows how to create AWS Bedrock Long-Term API Keys and integrate them with LLM Gateway.

## Prerequisites

- An AWS account with Bedrock access enabled
- LLM Gateway account (Pro plan required for provider keys) or self-hosted instance (free)

## Overview

AWS Bedrock supports **Long-Term API Keys** for simplified authentication. These keys provide direct API access without requiring IAM credentials or complex authentication flows.

## Create AWS Bedrock Long-Term API Key

<Steps>
<Step>
### Enable Model Access in Bedrock

1. Log into the **AWS Console**
2. Navigate to **AWS Bedrock** service
3. Go to **Model access** in the left sidebar
4. Click **Manage model access**
5. Enable the models you want to use (e.g., Claude 3.5, Llama 3)
6. Wait for access to be granted (usually instant for most models)

</Step>

<Step>
### Create Long-Term API Key

1. In AWS Bedrock console, navigate to **API Keys** in the left sidebar
2. Click **Create Long-Term API Key**
3. Enter a descriptive name (e.g., `llmgateway-production`)
4. Select the region where you want to use the key
5. Click **Create API Key**
6. **Important**: Copy the API key immediately - it's only shown once!
   - Store it securely in a password manager

</Step>

<Step>
### Choose Your Region

AWS Bedrock Long-Term API Keys are tied to specific regions. Common regions include:

- **US East (N. Virginia)**: `us-east-1` - Widest model availability
- **US West (Oregon)**: `us-west-2` - Good for West Coast workloads
- **EU (Frankfurt)**: `eu-central-1` - Best for European workloads
- **AP (Tokyo)**: `ap-northeast-1` - Best for Asia-Pacific workloads

The region you select when creating the key determines which models you can access.

</Step>
</Steps>

## Add to LLM Gateway

<Steps>
<Step>
### Navigate to Provider Keys

1. Log into [LLM Gateway Dashboard](https://llmgateway.io/dashboard)
2. Select your organization and project
3. Go to **Provider Keys** in the sidebar

</Step>

<Step>
### Add AWS Bedrock Provider Key

1. Click **Add Provider Key**
2. Select **AWS Bedrock** as the provider
3. Paste your Long-Term API Key
4. **Select Region Prefix** based on where you created your key:
   - **us.** - For US regions (`us-east-1`, `us-west-2`)
   - **eu.** - For European regions (`eu-central-1`, `eu-west-1`)
   - **global.** - For global/cross-region endpoints
5. Click **Add Key**

The system will validate your key and confirm the connection.

</Step>

<Step>
### Test the Integration

Test your integration with a simple API call:

```bash
curl -X POST https://api.llmgateway.io/v1/chat/completions \
  -H "Authorization: Bearer YOUR_LLMGATEWAY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "aws-bedrock/claude-3-5-sonnet",
    "messages": [
      {
        "role": "user",
        "content": "Hello from AWS Bedrock!"
      }
    ]
  }'
```

Replace `YOUR_LLMGATEWAY_API_KEY` with your LLM Gateway API key.

</Step>
</Steps>

## Region Prefix

The region prefix determines which AWS Bedrock endpoint your requests use:

- **us.** - US regions
  - Use for: `us-east-1`, `us-west-2`, and other US regions
  - Best for: US-based workloads, lowest latency in North America
  - Widest model availability

- **eu.** - European regions
  - Use for: `eu-central-1`, `eu-west-1`, and other EU regions
  - Best for: European workloads, GDPR compliance
  - Models deployed in European data centers

- **global.** - Global/cross-region endpoints
  - Use for: Multi-region redundancy
  - Best for: International workloads
  - May have different model availability

Choose the prefix that matches your Long-Term API Key's region.

## Security Best Practices

<Callout type="warn">**Important Security Notes**</Callout>

1. **Protect your Long-Term API Keys** - These keys provide direct access to AWS Bedrock
2. **Store keys securely** - Use a password manager or secrets management system
3. **Rotate keys regularly** - Create new Long-Term API Keys periodically and delete old ones
4. **Monitor usage** - Check AWS Bedrock console for API activity and costs
5. **Use separate keys per environment** - Don't share keys between development and production

## Troubleshooting

### "Invalid API key" error

- Verify you copied the complete Long-Term API Key
- Ensure you're using the correct region prefix (us., eu., or global.)
- Check that the key hasn't been deleted or expired in AWS Bedrock console

### "Model not available" error

- Verify you've enabled model access in AWS Bedrock console
- Check that the region where you created your key has access to the model
- Some models are only available in specific regions

### "Region mismatch" error

- Ensure the region prefix matches your Long-Term API Key's region
- Use `us.` for US regions, `eu.` for EU regions, `global.` for global endpoints

### Rate limiting

- AWS Bedrock has request quotas per model and region
- Monitor usage in AWS Bedrock console
- Consider requesting quota increases for high-volume workloads
