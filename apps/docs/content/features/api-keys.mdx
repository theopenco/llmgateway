# API Keys & IAM Rules

API keys are the primary method for authenticating with the LLM Gateway. This guide covers creating API keys, managing them, and configuring IAM rules for fine-grained access control.

## Overview

LLM Gateway provides comprehensive API key management with the following features:

- **Basic API Key Management**: Create, list, update, and delete API keys
- **Usage Limits**: Set spending limits on individual API keys
- **IAM Rules**: Fine-grained access control for models, providers, and pricing
- **Usage Tracking**: Monitor API key usage and costs
- **Status Management**: Enable/disable keys without deletion

## Creating API Keys

### Via Dashboard

1. Navigate to your project in the LLM Gateway dashboard
2. Go to the **API Keys** section
3. Click **Create API Key**
4. Provide a description for your key
5. Optionally set a usage limit
6. Click **Create**

<Callout type="warning">
	API keys are shown in full only once during creation. Make sure to copy and
	store them securely.
</Callout>

## Using API Keys

Once you have an API key, use it in the `Authorization` header of your requests:

```bash
curl -X POST "https://api.llmgateway.io/v1/chat/completions" \
  -H "Authorization: Bearer llmgtwy_your_api_key_here" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-4o",
    "messages": [{"role": "user", "content": "Hello!"}]
  }'
```

## API Key Management

### Listing API Keys

View all API keys for a project:

```bash
curl "https://api.llmgateway.io/v1/keys/api?projectId=your_project_id" \
  -H "Authorization: Bearer YOUR_SESSION_TOKEN"
```

### Updating API Key Status

Enable or disable an API key:

```bash
curl -X PATCH "https://api.llmgateway.io/v1/keys/api/{keyId}" \
  -H "Authorization: Bearer YOUR_SESSION_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"status": "inactive"}'
```

### Setting Usage Limits

Update the spending limit for an API key:

```bash
curl -X PATCH "https://api.llmgateway.io/v1/keys/api/limit/{keyId}" \
  -H "Authorization: Bearer YOUR_SESSION_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"usageLimit": "250.00"}'
```

### Deleting API Keys

Soft-delete an API key (can be recovered):

```bash
curl -X DELETE "https://api.llmgateway.io/v1/keys/api/{keyId}" \
  -H "Authorization: Bearer YOUR_SESSION_TOKEN"
```

## IAM Rules

IAM (Identity Access Management) rules provide fine-grained access control over what models, providers, and pricing tiers an API key can access.

### Rule Types

#### Model Access Rules

Control access to specific models:

- **Allow Models**: Only allow access to specific models
- **Deny Models**: Block access to specific models

```bash
# Allow only GPT-4o and Claude models
curl -X POST "https://api.llmgateway.io/v1/keys/api/{keyId}/iam" \
  -H "Authorization: Bearer YOUR_SESSION_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "ruleType": "allow_models",
    "ruleValue": {
      "models": ["gpt-4o", "claude-3-5-sonnet-20241022"]
    },
    "status": "active"
  }'
```

#### Provider Access Rules

Control access to specific providers:

- **Allow Providers**: Only allow access to specific providers
- **Deny Providers**: Block access to specific providers

```bash
# Only allow OpenAI and Anthropic providers
curl -X POST "https://api.llmgateway.io/v1/keys/api/{keyId}/iam" \
  -H "Authorization: Bearer YOUR_SESSION_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "ruleType": "allow_providers",
    "ruleValue": {
      "providers": ["openai", "anthropic"]
    },
    "status": "active"
  }'
```

#### Pricing Rules

Control access based on model pricing:

- **Allow Pricing**: Set constraints on what pricing tiers are allowed
- **Deny Pricing**: Block specific pricing tiers

```bash
# Allow only free models
curl -X POST "https://api.llmgateway.io/v1/keys/api/{keyId}/iam" \
  -H "Authorization: Bearer YOUR_SESSION_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "ruleType": "allow_pricing",
    "ruleValue": {
      "pricingType": "free"
    },
    "status": "active"
  }'

# Set maximum pricing limits
curl -X POST "https://api.llmgateway.io/v1/keys/api/{keyId}/iam" \
  -H "Authorization: Bearer YOUR_SESSION_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "ruleType": "allow_pricing",
    "ruleValue": {
      "maxInputPrice": 0.002500,
      "maxOutputPrice": 0.010000
    },
    "status": "active"
  }'
```

### Managing IAM Rules

#### List IAM Rules

```bash
curl "https://api.llmgateway.io/v1/keys/api/{keyId}/iam" \
  -H "Authorization: Bearer YOUR_SESSION_TOKEN"
```

#### Update IAM Rule

```bash
curl -X PATCH "https://api.llmgateway.io/v1/keys/api/{keyId}/iam/{ruleId}" \
  -H "Authorization: Bearer YOUR_SESSION_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "status": "inactive"
  }'
```

#### Delete IAM Rule

```bash
curl -X DELETE "https://api.llmgateway.io/v1/keys/api/{keyId}/iam/{ruleId}" \
  -H "Authorization: Bearer YOUR_SESSION_TOKEN"
```

## Usage Tracking

All API key usage is tracked and can be viewed in the dashboard or retrieved via API:

```bash
curl "https://api.llmgateway.io/v1/keys/api?projectId=your_project_id" \
  -H "Authorization: Bearer YOUR_SESSION_TOKEN"
```

The response includes:

- Current usage amount
- Usage limit (if set)
- Creation and last updated dates
- Status and IAM rules

## Best Practices

### Security

1. **Store Keys Securely**: Never commit API keys to version control
2. **Use Environment Variables**: Store keys in environment variables
3. **Rotate Keys Regularly**: Create new keys and delete old ones periodically
4. **Use IAM Rules**: Apply principle of least privilege with IAM rules

### Organization

1. **Descriptive Names**: Use clear, descriptive names for API keys
2. **Environment Separation**: Use different keys for different environments
3. **Usage Limits**: Set appropriate usage limits to prevent unexpected costs
4. **Team Keys**: Create separate keys for different teams or projects

### Monitoring

1. **Regular Audits**: Review API key usage regularly
2. **Set Alerts**: Monitor for unusual usage patterns
3. **Track Costs**: Use usage limits and pricing rules for cost control
4. **Log Access**: Monitor which keys are being used and when

## Error Handling

When API keys encounter IAM rule violations, the API returns specific error messages:

```json
{
	"error": true,
	"status": 403,
	"message": "Access denied: Model gpt-4 is not in the allowed models list"
}
```

Common error scenarios:

- Model not allowed by IAM rules
- Provider blocked by IAM rules
- Pricing limits exceeded
- API key disabled or deleted
- Usage limit reached

## Migration from Legacy Keys

If you have existing API keys without IAM rules:

1. **Backward Compatibility**: Existing keys continue to work without restrictions
2. **Gradual Migration**: Add IAM rules incrementally
3. **Testing**: Test IAM rules in development before applying to production
4. **Monitoring**: Monitor for access denied errors after implementing rules

<Callout type="info">
	API keys without IAM rules have unrestricted access to all models and
	providers, maintaining backward compatibility.
</Callout>
