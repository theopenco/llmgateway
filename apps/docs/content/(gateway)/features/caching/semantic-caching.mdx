[Gateway caching](/features/caching/gateway-caching) replays a response only for a byte-identical request. Semantic caching also replays it when the final user message differs from a cached one only in a short, fixed list of rewordings, so "How can I change my email address" reuses the answer to "How do I change my email address?".

<Callout type="info">
	Semantic caching is available on the [**Enterprise
	plan**](https://llmgateway.io/enterprise).
</Callout>

## Enable it

In the project's [**Preferences**](/learn/preferences), turn on **Enable request caching**, then pick a **Semantic caching** mode:

- **Off**: only byte-identical requests are served from the cache.
- **Shadow**: matches are recorded on the request log, but every request still goes to the provider.
- **On**: a matching request is served the cached response.

Matches expire with the cache duration you set for request caching. Turning request caching off sets semantic caching to **Off**; it does not come back when request caching is re-enabled.

## What matches

Everything except the final user message must be identical: model, provider, request parameters, the system prompt and every earlier message. The final user message must then be identical too, except for these differences:

| Ignored difference                                              | Example                                                                |
| --------------------------------------------------------------- | ---------------------------------------------------------------------- |
| "How can I" or "Where can I" at the start, for "How/Where do I" | "How can I export my data" / "How do I export my data"                 |
| "Which" at the start, for "What"                                | "Which plans do you offer" / "What plans do you offer"                 |
| "What's" at the start, for "What is"                            | "What's the capital of Australia" / "What is the capital of Australia" |
| The case of a question word at the start                        | "how do I reset my router" / "How do I reset my router"                |
| Trailing `?` and `.`                                            | "Track my order?" / "Track my order"                                   |
| Whitespace at the start or end                                  | "Track my order\n" / "Track my order"                                  |
| Curly apostrophes outside code                                  | "didn’t" / "didn't"                                                    |

The rewordings and the case rule apply only at the start of the message. Anywhere else, the same words can be quoted or mentioned text, as in "Translate to French: how can I help you".

Any other difference is a miss: another word or letter, a different case anywhere but a leading question word, numbers, symbols, word order, "please", contractions, spacing and line breaks. Code in backticks or fences is compared exactly. There is no similarity threshold and no embedding.

## Headers and auditing

A served hit returns `x-llmgateway-cache: HIT` and `x-llmgateway-cache-match: semantic` on `/v1/chat/completions`, `/v1/messages` and the AI SDK endpoint. It is logged and billed as a cached request.

Every match, served or not, writes `routingMetadata.semanticCache` on the request log: the cache key it matched and `served` (`false` in shadow mode).

## Limits

- Requests with `tools` and image generation models are skipped.
- The final message must be from the user and contain only text.
- `x-no-cache: true`, zero data retention and DevPass organizations bypass it, as with request caching. `/v1/responses` does not forward `x-no-cache`.
- If the lookup fails or takes longer than 250 ms, the request continues as a miss.
- It stops when the organization leaves the Enterprise plan.
