[Gateway caching](/features/caching/gateway-caching) replays a response only for a byte-identical request. Semantic caching also replays it when the final user message differs from a cached one only in a short, fixed list of ways that cannot change the answer, so "How can I change my email address" reuses the answer to "How do I change my email address?".

<Callout type="info">
	Semantic caching is available on the [**Enterprise
	plan**](https://llmgateway.io/enterprise).
</Callout>

## Enable it

In the project's [**Preferences**](/learn/preferences), turn on **Enable request caching**, then pick a **Semantic caching** mode:

- **Off**: only byte-identical requests are served from the cache.
- **Shadow**: matches are recorded on the request log, but every request still goes to the provider.
- **On**: a matching request is served the cached response.

Matches expire with the cache duration you set for request caching. Turning request caching off sets semantic caching to **Off**; it does not come back when request caching is re-enabled.

## What matches

Everything except the final user message must be identical: model, provider, request parameters, the system prompt and every earlier message. The final user message is then compared word by word, and only these differences are ignored:

| Ignored difference                                         | Example                                                          |
| ---------------------------------------------------------- | ---------------------------------------------------------------- |
| Case of a lowercase or capitalised word                    | "weather in paris" / "Weather in Paris"                          |
| A single space between symbols, outside code               | "2 + 3" / "2+3"                                                  |
| Whitespace at the start or end of the message              | "Track my order\n" / "Track my order"                            |
| Curly or straight quotes, full-width characters            | "didn’t" / "didn't", "１２" / "12"                               |
| Contractions                                               | "What's the capital" / "What is the capital", "don't" / "do not" |
| Trailing `?`, `.` and `!`                                  | "Track my order?" / "Track my order"                             |
| "please", unless it sits next to a quote                   | "Please summarise this" / "Summarise this"                       |
| "how can I" and "where can I" for "how do I", "where do I" | "How can I export my data" / "How do I export my data"           |
| A leading "which" for "what"                               | "Which plans do you offer" / "What plans do you offer"           |

## What never matches

Any other difference is a miss, because it can change the answer:

- a different word, even a near-synonym or a single letter: "legal" / "illegal", "news" / "new", "Does a landlord raise rent" / "Can a landlord raise rent";
- a different number, symbol or bracket: "1200" / "1500", "(2+3)\*4" / "2+3\*4";
- the same words in a different order: "from me to you" / "from you to me";
- the case of any other word: "CSS" / "css", "mW" / "MW";
- line breaks, indentation or repeated spaces, which shape unfenced code, poems and quoted strings;
- code in backticks or fences that differs in any character, whitespace included;
- a quoted "please": "Translate 'please' to French" never matches "Translate '' to French".

There is no similarity threshold and no embedding: two messages match only when they are equal after the differences above are removed.

## Headers and auditing

A served hit returns `x-llmgateway-cache: HIT` and `x-llmgateway-cache-match: semantic` on `/v1/chat/completions`, `/v1/messages` and the AI SDK endpoint. It is logged and billed as a cached request.

Every match, served or not, writes `routingMetadata.semanticCache` on the request log: the cache key it matched and `served` (`false` in shadow mode).

## Limits

- Requests with `tools` and image generation models are skipped.
- The final message must be from the user and contain only text.
- `x-no-cache: true`, zero data retention and DevPass organizations bypass it, as with request caching.
- If the lookup fails or takes longer than 250 ms, the request continues as a miss.
- It stops when the organization leaves the Enterprise plan.
