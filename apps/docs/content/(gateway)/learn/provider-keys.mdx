The Provider Keys page lets you add your own API keys from LLM providers (OpenAI, Anthropic, Google, etc.) to route requests directly through your accounts without additional gateway fees. The only optional charge is [data storage](/features/data-retention#storage-pricing): if your organization enables full data retention, stored requests are billed at $0.01 per 1M tokens from your credits.

## Adding a Provider Key

Click **Add Provider Key** to configure a new key:

- **Provider** — Select which provider this key belongs to
- **Custom name** — An optional label to identify the key
- **API key** — Your provider's API key
- **Base URL** — A custom endpoint replacing the provider's published one, for a built-in provider only where the deployment [allows the override](/self-host#provider-base-url-overrides): self-hosted deployments do by default, the hosted service does not. Configure the provider's own settings (such as an Azure resource) instead. [Custom providers](/features/custom-providers) always take a base URL.
- **Allowed models** — Optional allowlist restricting which models the key serves
- **Max spend** — Optional USD cap; the key is disabled once the spend attributed to it reaches the limit

<Callout type="info">
	The **Custom** provider requires the [**Enterprise
	plan**](https://llmgateway.io/enterprise), as does a custom base URL on a
	built-in provider where the deployment allows one. On other plans, existing
	[custom providers](/features/custom-providers) and keys with a custom base URL
	keep working and can be deactivated or deleted, but not added or edited.
</Callout>

## Provider Keys List

Each configured key shows:

| Field           | Description                                        |
| --------------- | -------------------------------------------------- |
| **Provider**    | The LLM provider (e.g., OpenAI, Anthropic)         |
| **Custom name** | Your label for the key                             |
| **Status**      | Active, inactive, or deleted                       |
| **Base URL**    | Custom endpoint if configured                      |
| **Token**       | Masked key: the first characters followed by `•••` |

<Callout type="info">
	Provider credentials are encrypted at rest because LLM Gateway must decrypt
	them to call the upstream provider. Gateway API keys work differently: new and
	rolled secrets are retained only as keyed HMAC-SHA-256 fingerprints, and
	authentication compares fingerprints instead of recovering the secret.
</Callout>

## Actions

For each provider key:

- **Edit description** — Change the key's display label
- **Rename** — Custom providers only: change the provider name, and with it the `<name>/<model>` prefix clients use
- **Restrict models** — Choose which models the key may serve
- **Set limits** — Cap the spend attributed to the key and its [rate limits](#rate-limits)
- **Deactivate** — Temporarily disable the key without deleting it
- **Delete** — Permanently remove the key

A key's secret and base URL cannot be edited — delete the key and add it again to change them. Custom provider tokens and base URLs can also be rotated through the [master API](/features/master-keys#update-a-custom-provider).

## Rate Limits

Each key can cap its own requests per minute or day (RPM/RPD) and prompt + completion tokens per minute or day (TPM/TPD), for example to match the quota of the upstream account. While a key is at any of its caps it is skipped: the next key for the provider serves the request, routing prefers other providers, and in hybrid mode the request falls back to LLM Gateway credits. If every key for the requested provider is capped and nothing else can serve the request, the gateway returns `429` with a `Retry-After` header.

Requests and tokens are counted once a request completes, so requests already in flight and the request that crosses a cap still finish. Leave a field empty for no limit.

The **limit mode** decides which requests a capped key still serves, with the same meaning as [provider rate limits](/features/routing#global-provider-rate-limits):

- **Strict** (default) — the key is skipped for every request.
- **Soft** — a [session](/features/sessions) already pinned to the key's provider keeps using the key, so multi-turn conversations, including encrypted reasoning on OpenAI and Azure, keep working. New sessions and requests without a session use other keys or providers.
- **Lax** — like soft, and requests that name the provider explicitly (`provider/model`) may also use the key. Automatic routing and fallback from another provider still skip it.

Exempt requests still count toward the key's caps. A conversation that replays encrypted reasoning issued by a key always keeps that key, whatever its mode, because no other key can verify the replay.

## Restricting a Key to Specific Models

Provider accounts often only have some of a provider's models enabled. Set
**Allowed models** on a key to list exactly the models it may serve — routing
then skips that key for anything else instead of sending a request the upstream
account will reject. Leave the list empty to serve every model the provider
offers.

The restriction also decides how a key is checked when you save it: a restricted
key is validated against one of its own allowed models rather than the
provider's default validation model, so a key with partial model access still
validates.

<Callout type="info">
	In hybrid mode, a model excluded by the restriction falls back to your credits
	rather than failing, so restricting a key never takes a model away from your
	projects.
</Callout>

<Callout type="info">
	When you use your own provider keys, requests are routed directly to the
	provider. You pay the provider's standard rates with no additional gateway
	markup — the only LLM Gateway charge is the optional [data
	storage](/features/data-retention#storage-pricing) cost when full data
	retention is enabled.
</Callout>
